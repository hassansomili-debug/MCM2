# منصة نضج MCM

منصة عربية RTL متكاملة لتقييم نضج الاتصال التسويقي وإدارة الرحلة من جمع الإجابات إلى التصحيح والتشخيص وخارطة الطريق والتقارير والبحث.

## التشغيل المحلي

لا توجد حزم خارجية مطلوبة؛ يكفي Python 3.9 أو أحدث:

```bash
cp .env.example .env
python3 server.py
```

ثم افتح `http://127.0.0.1:8000/`.

حسابات التطوير الافتراضية:

- مدير شركة: `sara@example.com` / `ChangeMe-2026`
- مدير منصة: `admin@nudj.local` / `Nudj-Admin-2026!`

غيّر القيم عبر متغيرات البيئة قبل أي تشغيل مشترك أو نشر.

## ما تم تنفيذه

- تسجيل، دخول، خروج، استعادة كلمة المرور، جلسات آمنة، مؤسسات متعددة، تبديل المؤسسة وRBAC للأدوار الخمسة.
- ملف شركة، موافقات خدمة/بحث، فريق ودعوات، وبوابة مستقلة للمشارك.
- أداة علمية بإصدارات غير قابلة للتعديل بعد النشر، معاينة واستيراد DOCX، مراجعة، اعتماد Pilot، نسخ وأرشفة.
- تقييم كامل مع autosave، حفظ واستكمال، مراجعة النواقص، تسليم مقفل، وإعادة تقييم.
- محرك تصحيح حتمي على الخادم: تطبيع 0–100، reverse coding، أوزان، missing data، درجات أبعاد، وMCM وSMCE منفصلان.
- سجل score runs غير قابل للاستبدال، تشخيصات، فجوات، أولويات، توصيات وخارطة 30/90/180 يومًا.
- لوحة ونتائج وتاريخ وقياس مرجعي محمي بحد أدنى للعينة.
- تقارير PDF فعلية، Excel من 10 أوراق، وحزمة SPSS قابلة للاستيراد مع codebook وlabels وsyntax.
- وحدة بحث مجهّلة، جودة بيانات، إحصاءات وصفية، سجل تدقيق، إشعارات، إعدادات ولوحة إدارة.
- واجهة SPA عربية متجاوبة مع مسارات hash وحماية مسارات حسب الدور وحالات تحميل/فراغ/خطأ.

## الاختبارات

```bash
python3 -m unittest -v tests/test_platform.py
```

تغطي الاختبارات رحلة الشركة كاملة، الحفظ والاستكمال، التصحيح، PDF، Excel/SPSS، العزل بين المؤسسات، RBAC، منع تسريب الملفات، رفض ملف المواصفات بوصفه بنك أسئلة، وصيغة reverse coding.

## الحالة العلمية

النسخة المزروعة `0.1.0` هي **Research Beta / PILOT** وبنودها تجريبية لتشغيل المنصة وليست أداة موثقة سيكومتريًا. ملف `متطلبات_منصة_نضج_MCM.docx` مواصفات منتج وليس بنك أسئلة، لذلك يرفضه مسار الاستيراد العلمي مع أخطاء واضحة. لا تُعرض صفة `VALIDATED` إلا بعد استيراد بنك البنود الحقيقي، مراجعة الخبراء، الدراسة الاستطلاعية، والتحقق العلمي.

## التخزين والنشر

التشغيل الحالي يستخدم SQLite ومسار القاعدة يضبط عبر `MCM_DB_PATH`. هذا مناسب للتطوير، ولخادم دائم بقرص/volume ثابت، لكنه **غير مناسب لملف `/tmp` على Vercel** لأن البيانات هناك مؤقتة. يحظر فحص الصحة النشر الصامت بإظهار `sqlite-ephemeral-warning` على Vercel.

لإطلاق إنتاجي دائم استخدم خادم Python دائمًا مع volume مشفّر الآن، أو نفّذ محول PostgreSQL وفق `migrations/001_postgresql.sql` قبل توجيه بيانات حقيقية. راجع `docs/deployment.md` و`docs/security.md`.
